# frontend

Vite + React + TypeScript SPA with TanStack Router (file-based, code-split per route),
TanStack Query, Tailwind CSS v4, shadcn/ui and Biome.

## Prerequisites

- Node 24 (via nvm)
- pnpm (`npm install -g pnpm`)

## Scripts

- `pnpm install` - install dependencies
- `pnpm dev` - dev server on http://localhost:5173 (`/api` is proxied to http://localhost:8000)
- `pnpm build` - type-check (`tsc -b`) and build to `dist/` (assets are referenced under `/static/`)
- `pnpm preview` - serve the production build locally
- `pnpm lint` - Biome check (lint + format + import order), read-only
- `pnpm format` - Biome format, writes changes

Every build also writes `stats.html` (git-ignored) - open it in a browser to inspect chunk sizes.

## Layout

- `src/main.tsx` - entry: creates the `QueryClient` and the router, renders the app.
- `src/routes/` - one file per route (TanStack Router file-based routing, see below).
- `src/routeTree.gen.ts` - generated by the router plugin. Committed, never edited by hand,
  excluded from Biome.
- `src/features/<feature>/` - feature code (UI helpers, on-demand
  modules, feature components.
- `src/lib/custom-fetch.ts` - transport used by the generated client (`customFetch`, `ApiError`, `errorMessage`).
- `src/components/ui/` - shadcn components.
- `src/api/` - generated by orval from `../openschema.json` (`../scripts/sync_schema.sh`): typed fetchers and
  TanStack Query hooks per tag (`api/<tag>/<tag>.ts`), models (`api/model/`), Zod schemas (`api/zod/`).
  Never edit by hand; this is the only way the app talks to the API.

## Routes and code splitting

The app must never ship as one bundle. Two mechanisms keep it split:

1. **Every route is its own chunk.** The router plugin (`autoCodeSplitting: true`) turns each file
   in `src/routes/` into a lazily loaded chunk. The first visit loads the shell
   (`index-*.js`), the stable `vendor-*.js` (react, react-dom, @tanstack) and the chunk of the
   visited route only. Links preload their target chunk on hover/focus (`defaultPreload: "intent"`).
2. **Heavy code is imported inside the handler that needs it.** Example in `src/routes/datasets.tsx`:

   ```ts
   async function handleExport() {
     const { exportDatasetsCsv } = await import("@/features/datasets/export-csv");
     exportDatasetsCsv(datasets.data);
   }
   ```

   `export-csv.ts` becomes its own chunk that is downloaded on the first click. Use the same
   pattern for Excel/PDF/chart/editor libraries: never import them at module top level.

### Adding a route

1. Create `src/routes/<path>.tsx` (e.g. `reports.tsx` -> `/reports`, `reports/$id.tsx` ->
   `/reports/:id`, `index.tsx` -> `/`). Export a `Route` from `createFileRoute` with the matching
   path string; the plugin fixes the string up if it is wrong:

   ```tsx
   import { createFileRoute } from "@tanstack/react-router";

   export const Route = createFileRoute("/reports")({
     component: ReportsPage,
   });

   function ReportsPage() {
     return <h1>Reports</h1>;
   }
   ```

2. Run `pnpm dev` or `pnpm build` - the plugin regenerates `src/routeTree.gen.ts`; commit it.
3. Link to it with `<Link to="/reports">` (paths are type-checked) and, if it should be in the top
   nav, add it to `navItems` in `src/routes/__root.tsx`.

Data fetching: use `useQuery`/`useMutation` from `@tanstack/react-query` with the feature's
the generated hooks (`useListDatasets`, `useCreateDataset`, ...) and query-key helpers
(`getListDatasetsQueryKey()`); invalidate with `queryClient.invalidateQueries({ queryKey: ... })`.
